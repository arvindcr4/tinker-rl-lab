# Architecture Decision Records

Use ADRs for durable, cross-cutting choices that future maintainers or agents
could otherwise reopen without the original context.

1. Copy `0000-template.md` to the next numbered filename.
2. Keep the title concise and use one status: `proposed`, `accepted`,
   `superseded`, or `deprecated`.
3. Link the pull request and any superseding ADR.
4. Record consequences and rejected options, not only the chosen implementation.

ADRs are append-only decision history. Amend factual errors, but represent a
changed decision with a new ADR that supersedes the old one.
