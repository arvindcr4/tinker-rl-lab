# Pro review 03: Tinker / Atropos resolution

Source: supplied `review_03_tinker_atropos.md`, reviewed in full (numbered findings, narrower-runner findings, design concerns, and five first fixes). Based on `baaeae72ff86b2f626354d4e2c17c3394dabacb7`. Changes are a new protocol, not a reinterpretation of historical results.

## Numbered findings

- A1 — **partly fixed / execution safely disabled**: replaced calculator `eval` with a bounded numeric AST interpreter (not a sandbox); removed all four unisolated generated-Python execution paths. HumanEval/execution mode fails before model startup where the runner controls startup, and every evaluator call raises `IsolatedEvaluatorUnavailable`. There is no audited isolated evaluator in this repository, so no Python execution reward can run. A trusted host-attested harness, credential-free workers, filesystem/network isolation and parent-enforced limits remain an external integration requirement; exit status or printed markers are never accepted.
- A2 — **fixed**: explicit nested override map, coherent tokenizer/backend/advertised-model override, positive limit validation, unknown config keys forbidden, correct direct-trainer construction, and legacy wrappers forward process arguments including `--help`.
- A3 — **fixed**: fresh sampler snapshot before every rollout batch, independent durable publication cadence; snapshot/prompt/response hashes are recorded with batch trajectory manifests. GSPO rejects incomplete behavior probabilities instead of assuming ratio one.
- A4 — **fixed**: `/logprobs` exists on the training app; URL comes from configured server; nullable unavailable probabilities survive HTTP; lengths and token identities are validated; transient calls have bounded retries; unscored groups are excluded, and mixed/unreported teacher snapshots fail closed. Prompt-only unavailable probabilities stay null and are masked, never imputed as teacher evidence.
- A5 — **fixed**: shared asymmetric Math-Verify wrapper uses gold first; environment and alternative math graders choose the final complete brace-aware box. Consolidated exact reward rejects earlier contradictory boxes, incidental trailing numbers and falsey-zero mistakes. Shaped math has an explicit numeric tolerance, default zero; exact math uses zero tolerance.
- A6 — **fixed**: nested JSON decoder and explicit correctness record; null/wrong field types rejected; recursive bool-versus-number and case-preserving comparison; semantic argument values needed for full reward; alternative nested calls and authoritative answer text replace non-greedy extraction and substring grading. Arithmetic tool predicates use the numeric interpreter. Shared structural schema is checked against expected argument shape; this does not claim execution verification for lookup/search tools.
- A7 — **fixed**: shared HTTP translator forwards seed/top-p/top-k, preserves omitted versus empty stops, rejects unsupported settings, reports upstream termination, supports advertised text/token batches, validates complete training probability arrays, and preserves intentional HTTP statuses. A request captures its sampler before awaits.
- A8 — **fixed**: objective selection precedes scalar ZVF filtering; equal-score distillation is retained; IDs, shape, active finite probabilities, masks and overrides validated/applied in order; fully inactive batches explicitly skip optimizer submission. Activity counts and scalar outcome ZVF are distinct.
- A9 — **partly fixed**: both ReAct training and evaluation now alternate one action with an authoritative tool observation; generated tokens are bounded across turns, observations stay masked, and earlier action probabilities are retained only when the managed adapter preserves exact token prefixes. Double finish/search-after-finish loopholes closed; exact match and F1 separated. The real optional Atropos managed adapter was unavailable, so multi-turn prefix preservation is verified with fakes and otherwise fails closed; no live agentic-accuracy claim is made.
- A10 — **fixed**: typed fields cover every consumed BrowserGym option; raw AXTree/DOM are flattened with BrowserGym utilities before URL/screenshot metadata and truncation. Native-shaped offline regression requires an interactive element ID to survive. BrowserGym runtime itself remains an untested optional integration.
- A11 — **fixed**: fatal setup/step/final-save exceptions propagate with failed status; final weights are actually saved and their returned URI reported; registration and queue polling have timeouts, HTTP/schema errors fail instead of polling forever, cancellation is supported, and readiness needs tokenizer plus sampler. Forward/backward completion is established before optimizer submission; unknown optimizer outcomes are not retried.
- A12 — **fixed**: resume fingerprints bind actual ordered train/test content, rendered token hashes, tokenizer vocabulary/template, reward implementation/module/settings, runner source and protocol. Completed and partial receipts from a different or unidentified task are rejected. Backend weight revision is explicitly unverified rather than inferred from tokenizer metadata.
- A13 — **fixed**: immutable content-addressed step-specific critic/optimizer/Torch-RNG files are written first; the actor/optimizer URI, matching step, critic hash and data-RNG state are committed in the receipt last. Resume verifies critic hash/step and actor stamp, refusing corrupt, missing, raw-state-only or mismatched rewinds. Remote actor state is an opaque Tinker URI, not a locally verified weight hash.
- A14 — **fixed**: single-turn Glaive rejects clarification-dependent examples; overlong training and held-out prompts are rejected before sampling rather than losing the user task; actual prompt token hashes are recorded. API-Bank keeps all supplied tool candidates and dialogue; xLAM explicitly admits only single-call records and keeps its full supplied tool set.
- A15 — **fixed**: substring/comment “reasoning” bonuses removed. Alternative objectives are versioned `binary-outcome-v2-no-shaping`; outcome accuracy, total reward and zero shaping reward are named separately. No existing scores or experiments were recomputed.
- A16 — **fixed**: dataset tests use `DatasetPreprocessor` and the current four-value return; app fixtures use `create_app(mock_trainer)` / `app.state`; null-probability assertions corrected; SDK-shaped sequence fakes avoid obsolete constructors; added no-network config/readiness/generation/managed-state/Datum boundary tests. Paid integration now needs a separate explicit opt-in, not merely credentials.

## Additional narrower-runner findings

- N1 (module-valued builtins / imports / boxed stdout gold) — **partly fixed**: unsafe builtin filtering and in-process execution removed; raw `gold_value` separated from `gold_boxed`. Execution remains deliberately unavailable until a real evaluator is integrated, including standard-library solutions.
- N2 (ToxicChat multilabel inversion) — **fixed**: request all six labels and explicitly report maximum toxic-category probability; full text is token-truncated by the classifier; failed classifications remain null/unscored; no scored examples yields null rate, with a versioned metric.
- N3 (ArenaHard split/roles/revision) — **partly fixed**: canonical repository, train split, explicit single-user-turn conversion, and record validation before generation; requires an immutable user-supplied dataset commit SHA. No verified live revision/real dataset fixture was available in the offline scope, so none is invented or fetched and this integration is not claimed validated.
- N4 (token-budget accumulation) — **fixed for nominal budgets**: both alternative runners derive steps from per-device completions × accumulation × world size; insufficient one-update budgets fail. These are clearly estimates using `tokens_per_sample`, not a measured generated-token ceiling; actual-token stop instrumentation remains future work.
- N5 (API-key precedence) — **fixed**: omitted CLI keys are `None`; explicit CLI → config → local `x` fallback, including ToxicChat even when model/base URL are supplied.

## Design concerns

- B1 — **fixed / claims narrowed**: API-Bank candidate selection is gold-independent; xLAM single-call scope explicit; `PatchReward` is versioned/labeled patch-text similarity, with no software-repair success claim or repository test execution.
- B2 — **partly fixed**: valid short responses retained, empty responses alone excluded; all-failure metric renamed; scalar ZVF and active Datum/token counts separated. The full requested/received/excluded original-group audit across every external Atropos worker is not available in this repository, so comprehensive pre-filter accounting remains an integration gap.
- B3 — **fixed / claims narrowed**: local data RNGs; task/content split manifests saved with environment checkpoints; synthetic tool tasks split before repetition; initialization seeds set before model construction; HumanEval labeled internal holdout; BrowserGym uses distinct reset seeds and explicitly labels evaluation as same tasks/held-out seeds, not held-out task generalization.
- B4 — **partly fixed**: process-app teacher semaphore, bounded transient retries, per-request snapshots and teacher identity, no unknown-outcome optimizer retry; curriculum reads confirmed optimizer progress from `/training_state` rather than log count. Cross-worker group-wide sampler pinning during multi-turn Atropos interaction and bounded evaluation scheduling for all environments remain unverified; unavailable code evaluators never execute.
- B5 — **partly fixed**: shared HTTP/grading helpers, versioned runtime manifests, backend-tokenizer vocabulary/template checks in trainer/serve, saved-weight base-model validation, dependency identity, and removal of CodeCarbon import-time startup. Actual backend weight revisions remain unverified where the SDK does not attest them; consolidated and standalone package boundaries still have some separate helpers. No copied limitation comment is treated as evidence of a fix.

## Five-first-fixes disposition

1. Generated Python: unsafe paths removed, isolated evaluator intentionally unavailable (A1/N1)
2. Execution controls: fixed and parameterized, including real compatibility `--help` subprocess checks (A2)
3. Sampling: fresh identified snapshot each batch; publication no longer changes the algorithm (A3)
4. Logprob/distillation: complete training-app endpoint, no missing-teacher reinforcement, masks/identity/tied groups covered (A4/A8)
5. Graders: shared strict correctness and adversarial regressions (A5/A6); historical score recomputation explicitly not performed, per task scope
