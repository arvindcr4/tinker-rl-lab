# P1 Minimal Decisive Experiment (minimal-decisive-experiment.md contract)

Role executed: experiment planner optimizing decision value per cost.
Input taken from the P1 Hypothesis Stress Test handoff (harness-vs-capability
audit of the "incapable" cluster, with its pre-registered revision and
hard-kill triggers). All artifact paths below were verified to exist before
this design was written; every number was re-read from disk.

---

## Input (placeholders filled per the contract's fill guide)

**Research question.** Is the low-R̄ "incapable" cluster of the P1 scaling
analysis — Qwen3-8B anchor R̄ = 0.2854 (`experiments/tinker-runs/results/scale_gsm8k_qwen3-8b.json`)
and Nemotron-120B anchor R̄ = 0.1750 / R_max = 0.1820
(`frontier_gsm8k_nemotron-120b.json`, `scaling_law_iter117_meta.json`) — a
capability-class effect (instruct-vs-base), or a harness artifact
(mislabeled checkpoints + hardcoded ChatML template + 512-token cap on a
thinking-mode model)?

**Decision needed.** Whether the paper keeps the bimodality/capability-class
clause ("dominant axis is capability class; R_max bimodal, gap 0.531,
`scaling_law_iter125_bimodality.tsv`") or re-attributes the dominant axis to
harness compatibility, withdraws the bimodality clause, and re-derives all
class claims from verified labels before publication.

**Resource limit.** Zero new training compute. One sampling-only Tinker job,
model ≤ 8B, ≤ 600 completions, plus ~half a day of scripting. Everything else
is pure re-analysis of files under `experiments/results/` and
`experiments/tinker-runs/`.

## 1) Setup

Three stages, strictly cheapest-first. Stage A is free and can hard-kill on
its own; Stage B is the only stage that touches the Tinker API.

### Stage A — Label audit (pure re-analysis, ~30 min, decides the hard-kill trigger)

Script joins, for each of the 5 anchors in
`experiments/results/scaling_law_iter117_meta.json`:
`anchors[i].trace_file` → the trace JSON's `model` field
(`experiments/tinker-runs/results/*.json`) → the matching `model_id` row in
`experiments/results/base_instruct_paired.tsv` → the `capability_class` label
the paper actually uses (`experiments/results/scaling_law_iter129_capability_scaling.tsv`).
Output: a 5-row verification table (anchor, trace model ID, paired-tsv
checkpoint label, iter129 class label, agree/contradict).

**Feasibility pre-check already run for this design (results below must be
formally reproduced by the Stage-A script, but they indicate the hard-kill
condition FIRES):**

- `scale_gsm8k_qwen3-8b.json` records `model = "Qwen/Qwen3-8B"` — the exact
  `model_id` of the **Inst** row of `base_instruct_paired.tsv`
  (row `Qwen3-8B / Inst / Qwen/Qwen3-8B / train_pre_rl = 0.2925`). The Base
  checkpoint is a different string (`Qwen/Qwen3-8B-Base`) and scores
  **0.8250** pre-RL in the same file. Yet
  `scaling_law_iter129_capability_scaling.tsv` labels this anchor
  `dense-base / base`. The anchor R̄ (0.2854) matches the Instruct row
  (0.2925) and is nowhere near the Base row (0.8250). The class labels are
  not merely unverified — the paired file shows them **inverted** for this
  family.
- The Nemotron anchor's trace records
  `model = "nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16"` — an **A12B MoE**
  — while `scaling_law_iter117_meta.json` and iter129 label it
  `family = dense / dense-base`. A second independent label error.
- Two additional harness facts discovered while verifying feasibility, which
  reshape Stage B (see below):
  1. **No transcripts exist anywhere.** Trace JSONs store only per-step
     scalars (`reward_trace`, `step_log`); `experiments/tinker-runs/logs/*.log`
     store only per-step reward lines. The handoff's "sample 50 zero-reward
     rollouts from the anchor logs" is impossible as literal re-analysis;
     transcripts must be regenerated by sampling.
  2. **The run scorer already contains the handoff's "lenient extractor."**
     `experiments/tinker-runs/scripts/tinker_parallel_runner.py::reward_math`
     falls back to the last number in the completion after trying `\boxed{}`.
     So the "lenient re-score" arm of the handoff is near-vacuous as
     specified; the live harness suspects are instead (a) the hardcoded
     ChatML `<|im_start|>` prompt applied to every model regardless of
     family, and (b) `max_tokens=512` at `temperature=0.8` on Qwen3-8B, a
     thinking-mode hybrid that will spend its budget inside `<think>` and be
     truncated before any final answer (last-number fallback then scores a
     wrong intermediate number).

### Stage B — Transcript regeneration + re-score (sampling-only, Tinker, ≤ 600 completions)

Only the ≤ 8B anchor is eligible; Nemotron-120B (120B) is over the model cap
and is handled in Stage C by forensics only. Sample **Qwen/Qwen3-8B** (the
exact string from the trace) on 150 GSM8K train prompts drawn with the run's
seed (seed=42, same loader as `tinker_parallel_runner.py`), under two
conditions, 2 samples per prompt = **600 completions total**:

- **B1 (harness replica):** the run's exact prompt construction (hardcoded
  ChatML system+user template, `SYSTEM_PROMPT_MATH`), `max_tokens=512`,
  `temperature=0.8`, `top_p=0.95` — reproducing the anchor's measurement
  conditions at step 0 (no LoRA; the anchor is flat from step 1, R̄≈first5_avg,
  so step-0 sampling is a faithful stand-in and needs no checkpoint).
- **B2 (harness fixed):** same prompts, same decoding, but the model's own
  chat template with thinking disabled (or, if the renderer cannot disable
  thinking, `max_tokens=2048` so reasoning can complete).

Score every completion with the original `reward_math`. Classify each
zero-reward B1 completion into: (i) correct-but-unparsed (correct final
answer string present; scorer missed it), (ii-a) truncated-before-answer
(hit the 512-token cap mid-reasoning, no final answer emitted), (ii-b)
genuinely wrong completed answer, (iii) degenerate/empty. Report (i) alone
(the handoff's verbatim trigger) and (i)+(ii-a) (harness-attributable total)
separately.

### Stage C — Cluster-statistic recomputation (pure re-analysis, ~1 h)

Substitute the corrected Qwen3-8B value (B2 mean reward; and the paired-tsv
Base value 0.8250 as a cross-check) into the 5-anchor pool and recompute:
sorted R_max gaps and largest gap (vs 0.5313), the dip statistic
(vs 0.5216, p=0.056, `scaling_law_iter125_bimodality.tsv`), and the
cross-scale slope on log10 N. For Nemotron-120B, no re-sampling is possible
under the budget; record the trace forensics instead — peak step reward
**0.875** at step 3 amid 55% zero-reward steps (a model that scores 87.5% on
one step is not incapable; rise-then-fall under a wrong-family ChatML
template is consistent with harness-induced collapse) — and flag its
attribution as *unresolved within budget*.

## 2) Decision rule (pre-registered, from the handoff, operationalized)

- **Hard-kill (Stage A):** if the R̄ = 0.2854 anchor's trace model ID equals
  the Instruct `model_id` of `base_instruct_paired.tsv` while the paper
  labels it base → the instruct-vs-base clustering is **void as stated**;
  every class claim must be re-derived from verified labels before any
  capability-class sentence survives. *Pre-check indicates this fires;
  the Stage-A script is the formal record.*
- **Revision (Stage B, either sufficient):**
  (a) ≥ 30% of zero-reward B1 completions are correct-but-unparsed
  (category i), **or** (b) B2 mean reward ≥ B1 mean reward + 0.15 (the
  sampling analogue of the handoff's lenient-re-score trigger, which is
  vacuous as literally specified because last-number fallback is already in
  the scorer), **or** (c) the Stage-C recomputation drops the largest gap
  below 0.25 or moves an anchor across the 0.2854↔0.8167 cluster boundary
  → re-attribute the dominant axis from "capability class" to "harness
  compatibility (template/parser/token budget)" and withdraw the bimodality
  clause.
- **Survival:** < 10% category-(i), B2 − B1 within ±0.05, all 5 Stage-A
  labels verified correct → the capability-class reading survives; proceed
  to the handoff's next-cheapest test (matched base-vs-instruct pair, same
  family, ≥ 3 seeds, step-1 solve rate stratified to [0.1, 0.9], slope
  trigger +0.05/decade with bootstrap 95% CI excluding 0).
- **Indeterminate band:** category-(i) in [10%, 30%) and B2 − B1 in
  (0.05, 0.15) → neither clause survives nor is withdrawn; the paper must
  downgrade the claim to descriptive wording (see §4) pending the matched
  pair.

## 3) Success threshold

The experiment succeeds if it lands in exactly one pre-registered branch:
every quantity in §2 computed and archived (Stage-A table, B1/B2 per-completion
scores + classifications, Stage-C recomputed gap/dip/slope) under
`experiments/results/` with an iter-style meta JSON. Total cost cap:
0 training steps, ≤ 600 sampled completions on one ≤ 8B model, ≤ half a day.
Note the asymmetry that makes this decisive: the handoff's triggers fire on
"either" incapable anchor, so Qwen3-8B alone can force revision even though
Nemotron cannot be re-sampled under the model cap.

## 4) Failure interpretation

- **If Stage B cannot run** (Tinker renderer cannot reproduce the template,
  model string no longer served): Stage A + Stage C alone still execute, and
  the Stage-A pre-check already voids the clustering *as stated*. Fallback
  action (one, concrete): rewrite the P1 claim from "capability class
  (instruct-vs-base) is the dominant axis" to the strictly descriptive
  "pre-RL harness-measured accuracy separates the anchors" — no causal class
  language — and mark Nemotron-120B as a single-seed case study with a
  family-label erratum (MoE, not dense).
- **If results land in the indeterminate band:** same descriptive downgrade,
  plus the matched-pair experiment is promoted from "next-cheapest" to
  "required before resubmission."
- **If survival branch:** the bimodality clause stands, but the two label
  errata (Qwen3-8B class, Nemotron family) must still be corrected in
  `scaling_laws.tex` and the iter129 table — survival of the mechanism does
  not repair the bookkeeping.
