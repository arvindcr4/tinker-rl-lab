\paragraph{What the manifest cannot bind.}
The earliest committed source whose experiment list contains both tags is
\path{experiments/tinker-runs/scripts/tinker_parallel_runner.py} at commit
\texttt{c68110a2} (blob \texttt{c5f3a67e}); that this exact source executed the
runs is not proven. Raw per-group reward vectors and raw completions were not
stored, so ZVF can be re-read from the stored step log but not recomputed
independently from rewards. No evaluator beyond the in-runner reward exists for
these cells. The SDK version is inconsistent across records (the ethics text
states \texttt{tinker==0.16.1}; the Hub model cards state v0.18.1), and the
model cards list \texttt{openai/gsm8k} as the dataset for these tool-use runs.

\paragraph{Alternative explanations the record cannot exclude.}
In the candidate source, the reward is graded: any completion whose stripped
decoded text parses with \texttt{json.loads} earns 0.3, a matching tool name
adds 0.4, and the expected argument keys add 0.3. A per-step mean of exactly 0
over 30 steps therefore means that none of the $2\times8$ completions per step
was accepted by a strict whole-string JSON parse; leading prose, reasoning
text, or code fences would all score 0. The prompts are 10 in-source synthetic
requests wrapped in Qwen ChatML markers for both models, including
Llama-3.1-8B-Instruct, and the system prompt lists five tools (calculator,
weather, search, reminder, translate), which differs from the tool list in the
earlier data-provenance text. With no stored completions, policy failure,
parser strictness, and chat-template mismatch are confounded, and ZVF $=1$
cannot distinguish ``no contrast to learn from'' from ``reward channel
disconnected''. A positive control (scoring reference completions through the
same reward) and stored completions are required before these cells can
diagnose anything.

\paragraph{Immutable-cohort contract.}
Every future empirical display must bind run IDs and source hashes to checkpoint
and tokenizer revisions, runner/objective version, dataset split, evaluator,
metric window, logging cadence, aggregation rule, seed count, completion status,
and evidence tier. A training-step count is not a logged-observation count.
