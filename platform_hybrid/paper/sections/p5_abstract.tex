\begin{abstract}
Papers comparing RL algorithms for LLM post-training report a \emph{label}---GRPO,
DAPO, Dr.GRPO, GSPO---and treat the surrounding software stack as an
implementation detail. Our position is that this convention is backwards: on the
evidence available to us, the stack is a material part of the reported result,
and a label without its stack is not a reproducible experimental
specification. Three exhibits motivate the reporting standard. First, a
nominal backend comparison of ``GRPO on Qwen3-8B/GSM8K'' spanned final training
rewards from $5.0\%$ (TRL) to $85.6\%$ (Tinker): a $17\times$ same-label swing.
It is not a backend comparison. The Tinker run used the \emph{Base} checkpoint
and the TRL run Qwen3-8B (Instruct); Qwen3-8B (Instruct) on the same Tinker
harness reaches $0.338$, so the checkpoint switch alone accounts
for $64\%$ of the gap, and the remainder is still confounded by reward function,
prompt and chat template, decoding, batch shape ($2{\times}8$ vs.\ $1{\times}8$),
data subset, and loss/optimizer implementation. The ``matched'' configuration
file in the repository describes neither run. Second, the label ``DAPO'' was
attached to two runs that differ in model, task, $G$, steps, and seeds, and the
closed-stack ``dapo'' arm is an advantage-clip variant, not DAPO; within each
stack, switching GRPO$\to$``DAPO'' moved mean Zero-Variance Fraction (ZVF) from
$0.25$ to $0.00$ on the open trainer (by construction of dynamic sampling) and
from $0.567$ to $0.578$ on the closed one. Third, in a 12-cell head-to-head of
four labels (surrogate implementations) on one fixed stack (3 seeds each), mean last-10 reward spans
$0.033$ ($0.710$--$0.744$); this is neither shown to be within noise nor shown
to be a difference: unpaired equivalence tests need margins of about $\pm0.19$, and in a
seed-paired analysis two contrasts (dapo$-$gspo, drgrpo$-$gspo) exclude zero at
90\% but not at 95\% confidence. We therefore
propose an eight-item \emph{minimum reportable
stack}---loss form, reference-policy/KL handling, sampler/backend/precision
\textbf{(including base-checkpoint identity: revision/hash)}, per-step ZVF/GU
trajectory, group-size schedule, disjoint held-out split,
decontamination plus a parser-robustness probe, and held-out pass@$k$
curves alongside pass@1---each item earning its place via a
documented ranking-relevant lever. We call out base-checkpoint identity explicitly
because in our backend exhibit an \emph{undisclosed} checkpoint switch was the
largest single lever: the ``stack'' effect is only interpretable once the base
checkpoint is pinned and reported alongside the framework. We formalize an RL-reproducibility threat
model with flip-risk grades R0--R5, specify a toolchain (manifest emitter, stack
diff with CI verdicts, registry, auditor badge, and citation-lever tracer) that
makes the standard enforceable, and close with a call to action for venues.
\end{abstract}
