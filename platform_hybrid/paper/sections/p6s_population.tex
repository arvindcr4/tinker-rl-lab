\section{Populating the Registry from Real Artifacts}
\label{sec:p6-population}

A registry seeded with hypothetical entries would not test the artifact against
real reporting gaps. All \NSTACK{} seed stack records derive from concrete
artifacts of this program (Table~\ref{tab:p6-entries-summary}): framework config dumps
and runs for Qwen3-8B/GSM8K, the open Colab trainer audit, the managed-runtime
head-to-head, the N2 same-stack four-method run, two W\&B PPO/REINFORCE runs,
and the zvf-iter130 risk-index batch. Entries marked with a \texttt{run\_config}
block were regenerated from the run sources with per-field provenance; the
others remain hand-entered.

\paragraph{Family A: the released config dumps.}
The four entries \texttt{trl/verl/openrlhf/tinker_grpo_qwen3-8b_gsm8k} are
mechanical translations of the 44-field per-framework dumps shipped at
\texttt{experiments/framework_config_dumps/}, since regenerated from the run
scripts where those exist. The dumps were written post hoc for reviewers and
do not describe the runs actually executed (e.g.\ placeholder checkpoint
hashes; TRL LoRA rank and completion length differ from the TRL script), so
the generated \texttt{run\_config} values take precedence. Translation preserved every honesty marker in the
dumps: the eleven \texttt{managed_by_tinker} nulls (including \texttt{kl.beta}
and \texttt{importance_sampling.granularity}), the genuine OpenRLHF deviations
($\beta{=}0.02$; sequence-level importance granularity), the Base-vs-Instruct
model confound on the managed runtime, and the fact that the veRL and OpenRLHF
rows of \texttt{framework_comparison.json} are dry-run placeholders (their
\texttt{telemetry} item is therefore null and their \texttt{outcomes} empty).
Where a run script fixes a value the dump left null, the regenerated value
replaces it (e.g.\ managed \texttt{kl.beta}${}=0$, provenance \texttt{code}).

\paragraph{Family B: the open Colab trainer (E3 audit).}
Four entries record the arms of the E3 open-trainer audit (\ifdefined\ANONYMOUSBUILD
logged to W\&B; project name withheld for review\else W\&B project
\texttt{zvf-colab-experiments}\fi): base GRPO, Dr.~GRPO (both deltas
implemented), DAPO (clip-higher and KL removal \texttt{implemented}; dynamic
sampling \texttt{surrogate}, because a zero-variance group is resampled at most
twice and then dropped rather than refilled; token-level loss \texttt{absent},
since the loss uses a sequence-level ratio; overlong shaping \texttt{absent},
being inapplicable at toy completion lengths), and an adaptive-$G$ arm whose
\texttt{group_size_schedule} records the live escalation rule ($G$
$4{\to}6{\to}8$ on ZVF spikes). These runs are toy-scale and their outcome
fields (held-out delta $+0.50$ to $+0.575$; the DAPO arm's mean ZVF $0.00$ at
$+45\%$ rollouts) are directional evidence only---but the \emph{records} are
exact, because the trainer's backward pass is open.

\paragraph{Family C: the managed-runtime head-to-head.}
Four entries record the 12-cell head-to-head (Qwen3.5-4B, GSM8K, three seeds
per arm) in which the four variant labels spanned $0.034$ in last-10
training reward ($0.710$--$0.744$; not shown equivalent, and two seed-paired
contrasts exclude zero). Their delta status arrays are written from the
client-side run scripts and differ sharply from Family B's: the ``dapo'' arm
implements only KL removal (its clip acts on the advantage, and there is no
dynamic sampling), the ``gspo'' arm implements neither sequence-level
component (its loss has no importance ratio), and the ``drgrpo'' arm
implements both removals in client code.

\paragraph{Family D: N2 same-stack isolated variants.}
Three entries (aero, gift~\citep{gift2025}, areal~\citep{areal2025}) record
the same managed runtime as Family C but with a different \emph{label} per
cell. The N2 four-method run holds the sampler, $G{=}8$, seed 0, prompt pool,
and step count fixed, so each per-method contrast against GRPO holds those
fields fixed; it is still one seed, and the method-specific code paths
differ. Step-bootstrap intervals over the last 10 steps exclude zero for
several contrasts
\ifdefined\SUBMISSIONBUILD(Appendix~\ref{sec:p6-measured})\else(Section~\ref{sec:p6-measured})\fi,
but they are single-trajectory intervals, not seed-level effects, and the run
is near ceiling ($72.5\%$ of GRPO's last-10 groups are all-correct). Each entry
marks its component \texttt{implemented} although its own note says the
variant machinery is closed; the governance rule
(Appendix~\ref{sec:p6-governance}) allows at most \texttt{surrogate}, so we
flag these statuses for downgrade. The AERO record cites
RL-ZVP~\citep{le2025rlzvp}, whose mechanism (entropy-guided advantage shaping)
differs from the record's, so ``aero'' is a program-internal label.

\paragraph{Family E: zvf-iter130 risk-index fixtures.}
Eleven records describe risk-index snapshots. They are not completed training
runs or validation of variant benefits. The source table
(\texttt{zvf\_iter130\_method\_risk.tsv}) does not document how its risk index
is computed, and some of its rows are identical across distinct conditions
(the two tool-use cells share every value), so not every row is an
independent measurement. Family E cannot validate variant performance or
training ZVF. With two dry-run placeholders and four toy-scale Colab runs,
the population is not 28 completed training runs.

\paragraph{What population taught us about our own reporting.}
The badge column is itself a finding. Our own released config dumps---built for a
reviewer-requested fairness audit---score 51 on the open frameworks: the veRL
and OpenRLHF dry-run records fully report items 2, 3, and 5 but item 1 only at
$0.10$ (a launcher YAML records \texttt{importance_sampling.granularity}, not
clip bounds) and items 4 and 7 not at all; the TRL record omits KL handling.
The open Colab arms score highest (84) not because the runs are better but
because an open backward pass plus an explicit ``no KL, no decontamination''
declaration makes nearly every field \emph{reportable}. Reproducibility supplements of the kind commonly shipped
with RL papers, ours included, do not automatically satisfy MIN-REPORT.
