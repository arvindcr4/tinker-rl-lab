## D.6 Replacement-scope lane narratives, 27 September 2026

Three things changed in how the lanes were executed, and each is recorded as a deviation in the lane's own result file. First, where a fail-closed controller blocked only on paperwork that the directive had superseded, the lane used a thin runner that calls the benchmark's native loop and native grader directly. Second, compute moved off AWS: E2, E6 and E9 ran on Google Cloud virtual machines, E1's grading ran in Modal sandboxes, and E13 ran locally. Third, every lane was served the same actor, `campaign-actor-bf16` (the base model with the seed809 adapter merged, §8.1), through vLLM with the non-thinking chat template. No lane went through the Tinker bridge implicated in the E4 failure mechanism (§8.1.2, §8.5), so that defect is not expected here, although the lanes' result files do not record their stop settings. The shared endpoint served at a 32,768-token context. E5 used a dedicated 65,536-token copy of the same weights because its banking prompts exceed 32k.

**E1 --- SWE-bench Multilingual.** This run covers the 16 wave-10 recovery tasks and the 174 tasks that the 12 September waves never reached, 190 tasks in all. ## D.9 Small-scale reruns: detail and per-lane caveats

Each lane's items, raw outputs and grader logs are kept so that every figure in Tables 8.A and 8.B can be recomputed (source: `outputs/e1_e14_small_scale_2026-09-26/PROTOCOL.md`).

For E12 the 151 rubric items come from only six generated applications, so they are not independent. The cluster-level test is an exact sign-flip test over the six per-app pass-rate differences (−0.042, +0.030, 0.000, −0.160, 0.000, −0.042), and it gives p = 0.25. The E12 grader is an LLM judge that is the same `Qwen/Qwen3.6-35B-A3B` base model as the base arm, so self-preference could favour the base arm.
